# Menu data

The menu is **data, not code**. Edit these CSVs; do not edit TypeScript to
change the menu.

| File | What it is | Provenance |
|---|---|---|
| `fastfood_nutrition.csv` | 515 real menu items, 8 US chains, measured nutrition | TidyTuesday 2018-09-04, from the `openintro` R package. CC0. |
| `menu.csv` | The entrées we serve | Generated from the above by `scripts/build-menu.mjs` |
| `extras.csv` | Drinks and sides | **Team-supplied.** The source dataset covers entrées only. |
| `web/public/menu-images/` | Item photos | [Fast Food Classification V2](https://www.kaggle.com/datasets/utkarshsaxenadn/fast-food-classification-dataset), CC0. Per-category, not per-item. |

## Photos

48 of 71 items have one, attached by `npm run data:images`. Coverage is uneven
because the source dataset has ten classes and our menu does not map onto them:

| Category | Photos | Why |
|---|---|---|
| burgers | 13/13 | direct `Burger` class |
| chicken | 17/18 | `Crispy Chicken` / `Sandwich` |
| sides | 4/5 | `Fries`, `Baked Potato` |
| desserts | 11/14 | `Donut` stands in |
| salads | 3/9 | no salad class |
| drinks | 0/9 | **no drink class at all** |

The same photo repeats within a category — the classifier cannot tell a Big Mac
from a Quarter Pounder, so every burger shows the same burger. Photographing
the drinks, salads and shakes yourselves is the obvious next step, and would
also give you per-item photos where it matters most.

## What is real and what is not

Every row carries its own provenance, and the database stores it, so the
report can state exactly where each number came from.

- **Item names** — real, from the published dataset.
- **Calories and protein** — real, measured, from the published dataset.
- **Categories** — our inference, keyword-derived in `build-menu.mjs`.
- **Prices — NOT REAL.** Every price is tagged `price_source=estimated`.

## The price problem, stated plainly

There is no open dataset of fast-food menu prices. The nutrition data is
published and citable; prices are not. So prices here are generated by a
deliberately crude heuristic (category base + a calorie-derived bump) that
looks like what it is.

**Before any figure from this system goes in the report, replace them.** Two
options:

1. Record real prices from an actual restaurant and edit the CSVs, setting
   `price_source=observed-<chain>-<date>`.
2. Import a priced dataset, e.g. Kaggle `graphquest/restaurant-menu-items`
   (~5k DoorDash items with prices), which needs a Kaggle API token:
   ```bash
   kaggle datasets download -d graphquest/restaurant-menu-items -p data/menu --unzip
   ```

The `price_source` column exists so a reviewer can check this in one query:

```sql
SELECT price_source, count(*) FROM menu_items GROUP BY price_source;
```

## Regenerating

```bash
node scripts/build-menu.mjs            # McDonald's (default)
node scripts/build-menu.mjs "Burger King"
cd web && npm run db:seed
```

Regenerating **overwrites** `menu.csv` and discards hand edits. Once you have
put real prices in, stop running the generator.
